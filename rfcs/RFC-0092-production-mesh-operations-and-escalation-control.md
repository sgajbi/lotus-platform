## Executive Summary

RFC-0091 made Lotus an enterprise data mesh foundation with governed products, telemetry,
certification, SLOs, access policies, evidence packs, and maturity-wave CI enforcement.

RFC-0092 closes the remaining gap between a certified mesh and an operated mesh. It adds a
production operating report that consumes mesh certification status and certification history,
then turns that evidence into:

1. current operating state,
2. certification trend posture,
3. regression detection,
4. product-level health posture,
5. escalation queues with owning repositories,
6. operator guidance suitable for release and customer-readiness decisions.

The report is generated by the existing mesh certification gate so it is part of normal platform
evidence, not a separate presentation artifact.

## Current Implementation Reality

Before this RFC:

1. the mesh certification gate could say whether the current evidence set passed,
2. evidence packs could write certification-history records,
3. operators still had to manually infer whether a clean run had enough history to be called
   production-ready,
4. regressions from previously certified posture were not represented as first-class operating
   evidence,
5. active issues did not have a compact escalation queue grouped by owner and product.

That was enough for first-wave certification. It was not enough for mature production operations.

## Implemented Capability

RFC-0092 implements:

1. `automation/generate_enterprise_mesh_operating_report.py`
   Builds and writes `lotus-enterprise-mesh-operating-report` artifacts.
2. `enterprise-mesh-operating-report.json`
   Machine-readable operator evidence generated under `output/mesh-certification/`.
3. `enterprise-mesh-operating-report.md`
   Human-readable readiness, drift trend, product posture, escalation, and guidance summary.
4. Certification-gate integration
   `automation/mesh_certification_gate.py` now writes the operating report with every gate run.
5. Unit coverage
   `tests/unit/test_enterprise_mesh_operating_report.py` and
   `tests/unit/test_mesh_certification_gate.py` protect operating-state classification,
   regression detection, escalation ownership, history counting, Markdown output, and gate
   integration.

## Operating State Model

The operating report uses these states:

| State | Meaning |
| --- | --- |
| `production_ready` | Current certification is clean and sufficient certification history exists. |
| `production_ready_limited_history` | Current certification is clean, but historical evidence is not yet deep enough to claim fully seasoned production posture. |
| `attention_required` | Current certification has warnings that must be reviewed before customer evidence export or further product promotion. |
| `blocked` | Current certification has errors or failed state; mesh promotion and customer evidence export must stop until owning repositories fix forward. |

This prevents Lotus from overstating maturity when the current run is clean but the operating
history is still shallow.

## Implementation Slices

### Slice 1 - Operating Report Generator

Implemented:

1. read current enterprise mesh certification status,
2. read certification-history records from evidence-pack output,
3. compute operating state,
4. compute drift trend,
5. compute regression since previous certification history posture,
6. compute product operating posture,
7. render JSON and Markdown artifacts.

### Slice 2 - Certification Gate Integration

Implemented:

1. write operating report artifacts during every mesh certification gate run,
2. keep certification status as the source evidence,
3. keep history records as optional trend evidence,
4. avoid making the report a product registry or duplicate certification engine.

### Slice 3 - Escalation And Operator Guidance

Implemented:

1. convert active certification issues into an escalation queue,
2. preserve issue severity, family, owner repository, product identity, remediation, and source
   evidence path,
3. emit state-specific operator guidance for clean, limited-history, warning, and blocked posture.

### Slice 4 - Meaningful Test Coverage

Implemented:

1. clean current state with limited history,
2. regression from certified to failed posture,
3. escalation owner preservation,
4. certification-history counting,
5. artifact write behavior,
6. certification-gate output integration.

### Slice 5 - Code Review, API Certification, And Governance Tightening

Completed:

1. verified the operating report consumes certification outputs rather than recreating product
   truth,

4. kept the new logic modular instead of expanding `mesh_certification_gate.py` with trend logic,
5. kept generated operating reports under `output/` because they are runtime evidence, not checked-in

## Acceptance Criteria

RFC-0092 is complete when:

1. the mesh certification gate writes an enterprise operating report on every run,
2. the report distinguishes clean-but-limited-history posture from seasoned production-ready
   posture,
3. regressions from prior certified state are detectable,
4. active issues are represented as escalation items with owners and product identity,
5. product operating posture is generated for every required maturity-wave product,
6. JSON and Markdown artifacts are generated deterministically,
7. targeted tests and platform feature-lane checks pass,
8. docs, context, wiki, skills assessment, and branch hygiene are complete.

## Non-Goals

This RFC does not:

1. add new domain products,
2. change gateway or Workbench APIs,
3. replace the certification gate,
4. expose customer evidence directly,
5. claim long production seasoning without certification history.

## Customer-Ready Positioning

After RFC-0092, the accurate claim is:

Lotus has an enterprise data mesh control plane with governed domain products, trust telemetry,
certification, discovery, dependency mapping, SLO/access/evidence controls, and an operator
readiness layer that tracks current health, certification trends, regressions, and escalation
ownership.

That is the right basis for customer conversations. Broader production maturity then becomes a
matter of operational run history and more product waves, not missing mesh foundation.
