Lineage is often discussed as an audit or engineering concern.

It is also a user experience feature.

When a front-office workflow shows a portfolio, cohort, exception, or action, the user is really asking a second question:

Why is this here?

If the answer is hidden in a backend job, a database table, or an implied convention, the screen may be correct but still hard to trust.

Good platforms bring the source evidence closer to the workflow.

Which source product supplied the candidate?
What version of the source contract was used?
Was the page complete?
Was the source ready, degraded, incomplete, or unavailable?
What boundary is explicitly not being claimed?

Those details do not all need to dominate the screen. But the product contract should carry them so the user experience can expose them when needed.

This changes the quality of the conversation.

Instead of debating whether a workflow is a black box, teams can inspect the evidence path. Instead of asking the UI to be trusted on its own, the platform lets the UI point back to governed source truth.

That is how lineage becomes practical, not decorative.
